## 1. 자바 개요 & 개발환경

### 1-1. 자바란?
| 항목 | 내용 |
|---|---|
| **정의** | 1995년 썬 마이크로시스템즈(현 Oracle)가 발표한 **객체지향 프로그래밍 언어** |
| **핵심 특징** | 플랫폼 독립성(WORA: *Write Once, Run Anywhere*), 객체지향, 자동 메모리 관리(GC), 강한 타입 검사 |
| **왜 쓰나?** | OS에 상관없이 동일하게 동작하고, 대규모 시스템(은행·공공·기업 백엔드, Spring, Android)에서 안정성과 유지보수성이 검증됨 |

### 1-2. JDK / JRE / JVM
```
┌──────────────── JDK (개발 도구 모음) ────────────────┐
│  javac(컴파일러), 디버거 등 개발 도구                  │
│  ┌──────────── JRE (실행 환경) ────────────┐         │
│  │  자바 표준 라이브러리(API)               │         │
│  │  ┌──── JVM (자바 가상 머신) ────┐       │         │
│  │  │  .class(바이트코드)를 실행    │       │         │
│  │  └──────────────────────────────┘       │         │
│  └─────────────────────────────────────────┘         │
└──────────────────────────────────────────────────────┘
```
- **JVM** : 바이트코드를 각 OS에 맞게 해석·실행 → *플랫폼 독립성의 비밀*
- **JRE** : JVM + 실행에 필요한 라이브러리 (실행만 할 때)
- **JDK** : JRE + 개발 도구 (개발자는 **JDK를 설치**한다)

### 1-3. 자바 프로그램 실행 과정
```
Hello.java  ──(javac 컴파일)──▶  Hello.class  ──(JVM 실행)──▶  결과 출력
 (소스코드)                        (바이트코드)
```
- 컴파일 시점에 문법/타입 오류를 미리 잡아준다 → **"컴파일 에러"**
- IntelliJ에서 ▶ 실행 버튼을 누르면 이 과정이 자동으로 수행되고, 결과물은 `out/production/...` 폴더에 생긴다.

### 1-4. 프로그램의 기본 구조
```java
package com.ohgiraffers.section01.literal;   // ① 이 파일이 속한 패키지

public class Application1 {                  // ② 클래스 (파일명과 같아야 함)
    public static void main(String[] args) { // ③ main 메소드 = 프로그램 시작점
        System.out.println("Hello");         // ④ 실행문 (끝에 세미콜론 ;)
    }
}
```
- **`main` 메소드**: JVM이 가장 먼저 찾아서 실행하는 **진입점(entry point)**. 형태를 그대로 외워두자.
- `System.out.println()` : 출력 후 줄바꿈 / `System.out.print()` : 줄바꿈 없음 / `System.out.printf()` : 형식 지정 출력

## 2. 리터럴 (Literal)

| 항목 | 내용 |
|---|---|
| **정의** | 소스코드에 **직접 적은 값 그 자체** (`123`, `1.23`, `'a'`, `"abc"`, `true`) |
| **왜 알아야 하나?** | 값의 형태에 따라 자바가 다루는 방식(타입)이 달라지기 때문 |

| 종류 | 예시 | 규칙 |
|---|---|---|
| 정수 | `123` | 기본 타입은 `int` |
| 실수 | `1.23` | 기본 타입은 `double` |
| 문자 | `'a'` | **홑따옴표**, 정확히 **한 글자**만 (`'abc'`, `''` → 에러) |
| 문자열 | `"abc"`, `""` | **쌍따옴표**, 빈 문자열도 가능 |
| 논리 | `true`, `false` | 두 값만 존재 |

### 리터럴 연산의 함정 ⚠️
```java
123 / 10        // 12      → 정수 ÷ 정수 = 정수 (소수점 버림)
123 % 10        // 3       → 나머지
123 + 0.5       // 123.5   → 정수 + 실수 = 실수
'a' + 'b'       // 195     → 문자는 내부적으로 숫자(유니코드)! 'a'=97, 'b'=98
"hello" + 123   // "hello123" → 문자열 + 무엇이든 = 문자열 합치기
"9" + 9         // "99"
9 + 9 + "9"     // "189"   → 왼쪽부터 계산: (9+9)=18 → 18+"9"="189"
```
> 💡 `+` 는 **양쪽이 숫자면 덧셈, 한쪽이라도 문자열이면 이어붙이기**. 계산은 **왼쪽부터** 진행된다.
> boolean 은 산술연산(`+ - * /`) 불가.

## 3. 변수 (Variable)

### 3-1. 개념
| 항목 | 내용 |
|---|---|
| **정의** | 값을 저장하기 위해 **메모리에 확보한 이름 붙은 공간** |
| **왜 쓰나?** | ① 값을 **재사용** ② 값에 **의미(이름)** 부여 → 가독성 ↑ ③ 값이 바뀌어도 한 곳만 수정 → 유지보수 ↑ |
| **언제?** | 같은 값을 여러 번 쓰거나, 계산 결과를 보관하거나, 값이 변할 때 |

### 3-2. 선언과 초기화
```java
int point;        // 선언: 자료형 변수명;   → int 크기의 공간을 point라는 이름으로 확보
point = 100;      // 대입(초기화): = 오른쪽 값을 왼쪽 변수에 저장
int age = 20;     // 선언과 동시에 초기화 (가장 많이 쓰는 형태)
```
> ⚠️ 지역 변수는 **초기화하지 않고 사용하면 컴파일 에러**.

### 3-3. 기본 자료형 (Primitive Type) 8가지
| 분류 | 자료형 | 크기 | 범위/비고 |
|---|---|---|---|
| 정수 | `byte` | 1 byte | -128 ~ 127 |
| | `short` | 2 byte | 약 ±3만 |
| | **`int`** ⭐ | 4 byte | 약 ±21억 (**정수 기본형**) |
| | `long` | 8 byte | 매우 큼, 리터럴 뒤에 `L` (`100L`) |
| 실수 | `float` | 4 byte | 리터럴 뒤에 `f` 필수 (`4.1f`) |
| | **`double`** ⭐ | 8 byte | **실수 기본형**, 더 정밀 |
| 문자 | `char` | 2 byte | 문자 한 개 (`'A'`), 내부는 유니코드 숫자 |
| 논리 | `boolean` | - | `true` / `false` |

- **왜 여러 개?** 저장할 값의 범위·정밀도에 맞게 메모리를 효율적으로 쓰기 위해.
- **실무 기준**: 정수는 `int`, 실수는 `double`을 기본으로, 범위가 부족할 때 `long` 사용.
- **`String`** 은 기본 자료형이 **아니다**. 문자열을 다루기 위해 자바가 제공하는 **클래스(참조 자료형)** — 그래서 대문자 S로 시작.

### 3-4. 변수 명명 규칙
**① 지키지 않으면 컴파일 에러 (필수)**
- 같은 범위 안에서 **중복 이름 불가**
- **예약어 불가** (`true`, `for`, `int`, `class` …)
- **대소문자 구분** (`age`, `Age`, `AGE`는 모두 다른 변수)
- **숫자로 시작 불가** (`1age` ✗, `age1` ○)
- 특수문자는 **`_` 와 `$` 만** 허용

**② 에러는 아니지만 지키는 약속 (관례)**
- **의미 있는 이름** 사용 (`s` ✗ → `name` ○)
- **카멜케이스(camelCase)**: `maxAge` ○ / `max_age` ✗
- 한글 변수명은 가능하지만 사용하지 않음
- 관용적 이름 활용: `sum`, `max`, `min`, `count`
- boolean은 **`is~`로 시작하는 긍정형 의문문**: `isAlive` ○ (`isDead`보다 읽기 쉬움)

## 4. 상수 (Constant)

| 항목 | 내용 |
|---|---|
| **정의** | **한 번 값을 넣으면 바꿀 수 없는** 메모리 공간. `final` 키워드 사용 |
| **왜 쓰나?** | 변하면 안 되는 값을 실수로 바꾸는 것을 **컴파일러가 막아줌** + 숫자에 의미 부여(매직넘버 제거) |
| **언제?** | 원주율, 최대 인원, 세율, 설정값 등 고정된 값 |

```java
final int AGE;
AGE = 20;      // 최초 1회 초기화 OK
// AGE = 30;   // ❌ 재대입 불가 → 컴파일 에러
int sum = AGE; // 값을 읽어서 사용하는 건 OK
```
- 이름 규칙: **모두 대문자**, 단어 연결은 **언더스코어** → `MAX_SIZE`, `TAX_RATE` (스네이크 대문자)

## 5. 오버플로우 / 언더플로우

| 항목 | 내용 |
|---|---|
| **정의** | 자료형이 담을 수 있는 범위를 **넘어서면 반대편 끝으로 값이 돌아가는** 현상 |
| **왜 중요?** | **에러 없이** 잘못된 값이 나와서 찾기 어려운 버그가 됨 |

```java
byte num = 127;  num++;   // -128  (오버플로우: 최대 → 최소)
byte num2 = -128; num2--; // 127   (언더플로우: 최소 → 최대)

int a = 1000000, b = 700000;
int  multi    = a * b;          // -79669248  ❌ int 범위 초과
long longNum  = a * b;          // -79669248  ❌ int끼리 계산하는 순간 이미 오버플로우!
long result   = (long) a * b;   // 700000000000 ✅ 계산 전에 하나를 long으로 바꿔야 함
```
> 💡 **결과를 담는 변수가 커도 소용없다.** *계산하는 순간의 타입*이 중요하다.

## 6. 형변환 (Type Casting)

| 항목 | 내용 |
|---|---|
| **정의** | 값의 자료형을 다른 자료형으로 바꾸는 것 |
| **왜 필요?** | 자바는 **같은 타입끼리만 연산**할 수 있어서, 타입이 다르면 맞춰줘야 함 |

### 6-1. 자동 형변환 (묵시적) — 작은 → 큰
```
byte → short → int → long → float → double
              char ↗
```
```java
byte bnum = 1;
long lnum = bnum;          // 자동 변환 OK (데이터 손실 없음)

int num1 = 10; long num2 = 10;
long result = num1 + num2; // 연산 시 큰 타입(long)으로 맞춰서 계산
// int result = num1 + num2; ❌ 결과가 long이므로 int에 못 담음

long eight = 8;
float four = eight;        // 8.0  정수 → 실수는 자동 변환
```

### 6-2. 강제 형변환 (명시적) — 큰 → 작은
```java
(바꿀자료형) 값
```
```java
long lnum2 = 8;
int inum2 = (int) lnum2;     // 큰 → 작은: 캐스트 연산자 필요

float fnum = 4.1f;
long lnum3 = (long) fnum;    // 4  → 소수점 버려짐 (데이터 손실)
```
- **언제?** 데이터 손실을 **감수하겠다고 개발자가 명시**할 때 ("내가 책임질게!")
- **주의**: 범위를 넘는 값을 강제 변환하면 오버플로우처럼 엉뚱한 값이 나온다.

## 7. 연산자 (Operator)

> **정의**: 값(피연산자)에 대해 계산·비교·논리 판단 등을 수행하는 기호

### 7-1. 산술 연산자 `+ - * / %`
```java
10 / 3   // 3  (정수끼리 나누면 소수점 버림)
10 % 3   // 1  (나머지)
```
- `%` 활용: **짝/홀수 판별** (`n % 2 == 0`), **배수 판별**, 자릿수 추출 (`123 % 10 → 3`)

### 7-2. 복합 대입 연산자 `+= -= *= /= %=`
```java
int num = 12;
num += 3;   // num = num + 3;  → 15
```
- **왜?** 코드가 짧아지고 의도("기존 값에 누적한다")가 명확해짐. 합계 누적 등에 자주 사용.

### 7-3. 증감 연산자 `++ --`
| 형태 | 동작 |
|---|---|
| **전위** `++num` | **먼저 1 증가** → 그 값을 사용 |
| **후위** `num++` | 현재 값을 **먼저 사용** → 나중에 1 증가 |
```java
int num = 15;
System.out.println(num++); // 15 출력 후 num=16
System.out.println(++num); // 17 (16→17 증가 후 출력)

int firstNum = 10;
int result = ++firstNum * 3; // 11 * 3 = 33
```
> 💡 단독으로 쓸 때(`num++;`)는 차이 없음. **다른 식 안에 섞일 때** 차이가 난다.

### 7-4. 비교 연산자 `== != > < >= <=`
- 결과는 항상 **boolean** (`true`/`false`)
- **문자열 비교는 `equals()`를 사용!**
```java
String str1 = "java", str2 = "java";
str1 == str2        // 같은 객체(주소)를 가리키는지 비교 → 리터럴은 우연히 true일 수 있음
str1.equals(str2)   // ✅ 내용(글자)이 같은지 비교 → 문자열은 항상 이것 사용
```
- 자바에는 **`===` 연산자가 없다**. 타입이 엄격해서 JS처럼 `1 == "1"` 자동 변환 비교를 하지 않음.
- `1 == '1'` → `false` (`'1'`의 유니코드 값은 49)

### 7-5. 논리 연산자 `&& || !`
| 연산자 | 의미 | 결과가 true인 경우 |
|---|---|---|
| `&&` (AND) | 그리고 | **둘 다** true |
| `\|\|` (OR) | 또는 | **하나라도** true |
| `!` (NOT) | 부정 | 반대로 뒤집음 |

```java
// 범위 검사: 1 <= num <= 100 ❌ 자바에선 불가
num >= 1 && num <= 100   // ✅
```
- 자바의 논리 연산은 **boolean만** 가능 (JS의 truthy/falsy 개념 없음 → `if (1)` ❌)

**단축 평가 (Short-circuit)**
- `&&` : 앞이 **false**면 뒤는 **실행 안 함** (어차피 false)
- `||` : 앞이 **true**면 뒤는 **실행 안 함** (어차피 true)
```java
int num2 = 10;
boolean r = false && ++num2 > 0;  // 뒤쪽 미실행
System.out.println(num2);          // 10 (증가 안 됨!)
```
- **활용**: 실패 가능성이 높은 조건이나 가벼운 조건을 앞에 두면 효율적. 반대로 뒤쪽 식에 `++` 같은 부수효과를 넣으면 **버그의 원인**.

### 7-6. 삼항 연산자
```java
(조건식) ? 참일때값 : 거짓일때값
```
```java
String result = (num > 0) ? "양수다" : "음수다";
int max = (a > b) ? a : b;
```
- **언제?** 조건에 따라 **값 하나를 골라 변수에 담을 때**. 간단한 if-else를 한 줄로.
- 너무 복잡하게 중첩하면 가독성이 떨어지므로 지양.

### 7-7. 연산자 우선순위 (높음 → 낮음)
```
()  >  단항(++ -- ! (형변환))  >  산술(* / % > + -)  >  비교(> < >= <=  >  == !=)
    >  &&  >  ||  >  삼항(?:)  >  대입(= += -= ...)
```
> 💡 헷갈리면 **괄호 `()`** 를 쓰자. 가독성도 좋아진다.

## 8. 메소드 (Method)

### 8-1. 개념
| 항목 | 내용 |
|---|---|
| **정의** | **특정 작업을 수행하기 위한 명령문들의 묶음** (다른 언어의 "함수") |
| **왜 쓰나?** | ① **중복 제거/재사용** ② 큰 문제를 작은 단위로 **분리** ③ 이름으로 의도를 표현 → **가독성** ④ 수정 시 한 곳만 고치면 됨 → **유지보수** |
| **언제?** | 같은 코드가 반복될 때, 하나의 기능으로 묶을 수 있을 때 |

### 8-2. 메소드의 구조
```java
 접근제어자  [static]  반환타입   메소드명   (매개변수목록)  {
   public              String    createString(String name, int age) {
       String profile = name + "님의 나이는 " + age + "세 입니다.";
       return profile;     // 반환값
   }
```

### 8-3. 호출 흐름 (Call Stack)
```java
main → methodA() → methodB() → methodC()
```
```
main 호출됨
methodA() 호출함
methodB() 호출함
methodC() 호출됨
methodC() 종료됨      ← 가장 나중에 호출된 것이
methodB() 종료됨      ← 가장 먼저 끝난다 (스택: 후입선출)
methodA() 종료됨
main 종료됨
```
> 💡 메소드가 끝나면 **자신을 호출한 곳으로 돌아가** 다음 줄부터 이어서 실행한다.

### 8-4. 전달인자(Argument) vs 매개변수(Parameter)
| 용어 | 위치 | 예시 |
|---|---|---|
| **전달인자** | 메소드를 **호출할 때** 넘기는 값 | `app2.printAge(10);` 의 `10` |
| **매개변수** | 메소드 **선언부**에서 값을 받는 변수 | `printAge(int age)` 의 `age` |

```java
app2.printUserInfo("판다", 3, '남');
public void printUserInfo(String name, int age, char gender) { ... }
```
> ⚠️ 매개변수의 **타입·개수·순서**를 정확히 맞춰야 한다. 안 맞으면 컴파일 에러.

### 8-5. 반환값 (return)
| 반환타입 | 의미 | return |
|---|---|---|
| `void` | 돌려줄 값 **없음** (출력 등 작업만 수행) | 생략 가능 / `return;` 은 메소드 종료 |
| `int`, `String` … | 해당 타입의 값을 **반드시** 돌려줌 | `return 값;` 필수 |

```java
String message = app2.createMessage();  // 반환값을 변수에 저장
System.out.println(app2.createMessage()); // 바로 다른 메소드의 인자로 사용
```
- **언제 반환?** 결과를 **호출한 쪽에서 이어서 사용해야 할 때** → 계산, 데이터 생성
- **언제 void?** 결과를 쓸 필요 없이 **동작만** 하면 될 때 → 출력, 저장

### 8-6. static 메소드 vs non-static(인스턴스) 메소드 ⭐
| 구분 | non-static | static |
|---|---|---|
| **소속** | **객체(인스턴스)** 에 속함 | **클래스** 에 속함 |
| **호출 방법** | 객체 생성 후 `변수명.메소드명()` | `클래스명.메소드명()` |
| **같은 클래스 내** | 객체 생성 필요 (main은 static이므로) | 클래스명 **생략 가능** |
| **언제 사용?** | 객체마다 다른 데이터를 다룰 때 | 객체 상태와 무관한 **유틸리티 기능** (예: `Math.max()`) |

#### 예시
static과 non-static: 언제, 왜 나눠 쓸까?
한 줄 정리

그 메소드가 "객체마다 다른 데이터"를 써야 하면 non-static, 그렇지 않으면 static을 써요.
1. 비유: 은행 계좌
```java
public class Account {
    String owner;   // 예금주 (계좌마다 다름)
    int balance;    // 잔액 (계좌마다 다름)

    // non-static: "이 계좌의" 잔액을 바꿈
    public void deposit(int money) {
        balance += money;
    }

    // static: 어떤 계좌인지와 상관없는 계산
    public static int calcInterest(int money, double rate) {
        return (int) (money * rate);
    }
}

Account a = new Account();   // 철수 계좌
Account b = new Account();   // 영희 계좌

a.deposit(1000);   // 철수 계좌에만 1000원이 들어감
b.deposit(500);    // 영희 계좌에만 500원이 들어감

Account.calcInterest(10000, 0.03);   // 누구 계좌인지 알 필요 없음 → 300
```
2. 언제 무엇을 쓸까?
	non-static (인스턴스 메소드)	static (클래스 메소드)
판단 기준	객체가 가진 데이터(필드)를 읽거나 바꿀 때	매개변수만으로 결과가 나올 때
예시	잔액 입금, 캐릭터 이동, 회원 정보 수정	최댓값 구하기, 단위 변환, 문자열 → 숫자 변환
자바 API 예시	str.equals(), str.length()	Math.max(), Math.random(), Integer.parseInt()
호출	new → 변수.메소드()	클래스명.메소드()

str.length()가 non-static인 이유를 생각해 보면 이해가 쉬워요. "어떤 문자열의" 길이인지가 있어야 답이 나오잖아요. 반대로 Math.max(3, 5)는 넘겨준 3과 5만 있으면 돼요. 그래서 Math 객체를 만들 필요가 없어요.

3. 왜 굳이 나눌까?
① 데이터가 어디에 있는지가 다르기 때문이에요
non-static 메소드는 객체마다 따로 있는 데이터를 다뤄요. 같은 deposit()이라도 a로 부르면 철수 잔액이, b로 부르면 영희 잔액이 바뀌어요. 그래서 반드시 "어느 객체인지" 가 정해져야 해요.
static 메소드는 클래스에 딱 하나만 있어요. 어떤 객체에도 속하지 않아요.
② 필요 없는 객체 생성을 막을 수 있어요

최댓값 하나 구하자고 매번 new Calculator()를 하는 건 낭비예요. static이면 객체 없이 바로 쓸 수 있어요.

③ 코드만 보고 의도를 알 수 있어요
Calculator.maxNumberOf()를 보면 "객체 상태와 상관없는 기능이구나" 하고 알 수 있어요.
calc.minNumberOf()를 보면 "이 객체와 관련된 동작이구나" 하고 읽혀요.

그래서 static 메소드를 calc.maxNumberOf()처럼 객체로 부르면 IntelliJ가 경고를 띄워요. 동작은 하지만 읽는 사람에게 잘못된 신호를 주기 때문이에요.

4. 오늘 코드에서 생긴 궁금증 풀기
Q1. main은 왜 static일까요?

프로그램이 시작되는 순간에는 아직 객체가 하나도 없어요. JVM이 객체를 만들지 않고 바로 호출할 수 있어야 하니까 main은 static이어야 해요.

Q2. Application1에서 왜 new Application1()을 했을까요?
public static void main(String[] args) {
    // methodA();          // ❌ 컴파일 에러
    Application1 app1 = new Application1();
    app1.methodA();        // ✅
}
public void methodA() { ... }   // non-static

main은 static이라 "어느 객체"인지 모르는 상태예요. 그런데 methodA()는 non-static이라 객체가 꼭 있어야 해요. 그래서 객체를 직접 만들어서 호출한 거예요.

누가 → 누구를 호출	가능?
static → static	✅ (같은 클래스면 이름만으로)
non-static → static	✅
non-static → non-static	✅ (같은 객체 안에서는 이름만으로)
static → non-static	❌ 객체를 만들어야 가능
Q3. 오늘 만든 Calculator에서는 뭐가 맞을까요?

솔직히 말하면 minNumberOf()도 maxNumberOf()도 매개변수만 사용해요. 기준대로라면 둘 다 static이 맞아요. 수업에서는 두 가지 호출 방식을 비교해 보려고 일부러 하나만 non-static으로 만든 예제예요.

5. 앞으로 판단하는 법

메소드를 만들 때 이렇게 물어보세요.

"이 메소드가 객체의 필드(그 객체만의 데이터)를 쓰나?"

예 → non-static
아니요 → static을 고려

## 9. 패키지 & import

### 9-1. 패키지 (package)
| 항목 | 내용 |
|---|---|
| **정의** | 관련된 클래스들을 묶어두는 **폴더(이름 공간)** |
| **왜 쓰나?** | ① 클래스를 **체계적으로 분류** ② **이름 충돌 방지** (다른 패키지면 같은 클래스명 가능) |
| **규칙** | 보통 회사 도메인 역순: `com.ohgiraffers.section01.method`, 모두 소문자 |

- 클래스의 **진짜 전체 이름** = `패키지명.클래스명` → `com.ohgiraffers.section01.method.Calculator`

### 9-2. import
| 항목 | 내용 |
|---|---|
| **정의** | 다른 패키지의 클래스를 **패키지명 없이 짧게 쓰도록** 미리 선언 |
| **위치** | `package` 선언 아래, `class` 선언 위 |

```java
// import 없이: 매번 풀네임 작성 😵
com.ohgiraffers.section01.method.Calculator calc =
        new com.ohgiraffers.section01.method.Calculator();

// import 사용 😊
import com.ohgiraffers.section01.method.Calculator;
Calculator calc2 = new Calculator();
int max2 = Calculator.maxNumberOf(30, 20);
```

### 9-3. static import
```java
import static com.ohgiraffers.section01.method.Calculator.maxNumberOf;
int max3 = maxNumberOf(30, 20);   // 클래스명까지 생략
```
- 편하지만 **어느 클래스의 메소드인지 알기 어려워** 남용하지 않는다.
- 같은 패키지의 클래스와 `java.lang` 패키지(`String`, `System`, `Math`)는 import 없이 사용 가능.

## 10. 자주 하는 실수 체크리스트 ✅

- [ ] 문장 끝 **세미콜론(`;`)** 빠뜨림
- [ ] 문자는 `' '`, 문자열은 `" "` — 헷갈리지 않기
- [ ] `long` 리터럴의 `L`, `float` 리터럴의 `f` 빠뜨림 (`float f = 4.1;` ❌)
- [ ] 정수끼리 나누면 소수점이 **버려진다**
- [ ] 큰 수 곱셈 시 **계산 전에** `(long)` 형변환
- [ ] 문자열 비교는 `==` 말고 **`equals()`**
- [ ] `1 <= x <= 100` 은 불가 → `x >= 1 && x <= 100`
- [ ] 반환타입이 void가 아니면 **반드시 return**
- [ ] 파일명과 `public class` 이름은 **같아야** 한다
- [ ] main(static)에서 non-static 메소드는 **객체를 만들어서** 호출
