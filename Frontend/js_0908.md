## 배운 개념

- **함수(Function)**: 특정 동작을 하나의 코드 묶음으로 정의하여 필요할 때 재사용할 수 있게 한다.

- **매개변수(Parameter)**: 함수를 정의할 때 외부의 값을 전달받기 위해 사용하는 변수

- **인수(Argument)**: 함수를 호출할 때 실제로 전달하는 값

- **반환(Return)**: 함수의 실행 결과를 호출한 위치로 돌려준다. `return`을 만나면 해당 함수의 실행은 즉시 종료된다.

- **함수 호이스팅(Function Hoisting)**: 함수 선언문은 코드 실행 전에 함수가 준비되기 때문에 선언 위치보다 앞에서도 호출할 수 있다. 반면 `const`, `let`을 이용한 함수 표현식은 변수 초기화 전에 사용할 수 없다. 선언 순서를 명확하게 하고 코드의 실행 흐름을 예측하기 쉽게 하기 위해 함수 표현식을 사용하기도 한다.

- **함수도 값이다**: JavaScript에서 함수는 값처럼 다룰 수 있다. 변수에 저장하거나, 객체의 프로퍼티 값으로 사용하거나, 다른 함수의 인수로 전달하거나, 함수의 반환값으로 사용할 수 있다.

- **고차 함수(Higher-Order Function)**: 다른 함수를 인수로 받거나 함수를 반환하는 함수

- **콜백 함수(Callback Function)**: 다른 함수에 인수로 전달되어 필요한 시점에 실행되는 함수

- **스코프(Scope)**: 변수를 사용할 수 있는 범위

- **렉시컬 스코프(Lexical Scope)**: 함수가 호출된 위치가 아니라 선언된 위치를 기준으로 바깥 스코프를 결정하는 규칙이다. 함수 내부에서 변수를 찾을 때 현재 스코프에 없으면 자신이 선언된 바깥 스코프로 올라가며 변수를 찾는다.


## 추가 학습 내용

- **`var` 호이스팅**
  - `var`로 선언한 변수는 코드가 실행되기 전에 변수 선언이 먼저 처리되고 `undefined`로 초기화된다.
  - 따라서 선언문보다 먼저 변수에 접근하면 `ReferenceError` 대신 `undefined`가 출력될 수 있다.

```javascript
console.log(value); // undefined

var value = 10;
```

- **호이스팅은 왜 발생하는가?**
  - JavaScript 엔진은 코드를 위에서 아래로 단순히 한 줄씩 실행하기만 하는 것이 아니라, 실제 실행 전에 변수와 함수 등 실행에 필요한 정보를 먼저 준비한다.
  - 이 과정 때문에 선언이 코드의 위쪽으로 끌어올려진 것처럼 보이는 호이스팅 현상이 발생한다.

- **`null`, `NaN`, `undefined`의 차이**
  - `null`: 개발자가 의도적으로 "값이 없음"을 나타낼 때 사용하는 값
  - `undefined`: 변수가 존재하지만 아직 값이 할당되지 않았거나, 함수에 필요한 인수가 전달되지 않은 상태 등을 나타내는 값
  - `NaN`: 숫자 연산이나 숫자 변환을 시도했지만 정상적인 숫자 결과를 얻을 수 없을 때 나타나는 값. `Not a Number`의 약자이지만 `typeof NaN`의 결과는 `"number"`이다.

- **클로저(Closure)**: 함수가 자신이 선언될 당시의 바깥 렉시컬 환경을 기억하여, 바깥 함수의 실행이 끝난 뒤에도 해당 환경의 변수에 접근할 수 있는 현상이다.

```javascript
function createCounter() {
    let count = 0;

    return function() {
        count++;
        return count;
    };
}

const counter = createCounter();

counter(); // 1
counter(); // 2
```

`createCounter()`의 실행은 끝났지만 반환된 내부 함수가 `count`를 계속 참조하고 있기 때문에 상태가 유지된다.

- **클로저가 실무에서 유용한 이유**
  - 데이터 은닉과 상태 관리에 유용하다. 내부 변수에 외부에서 직접 접근할 수 없고, 내부 함수를 통해서만 접근하거나 값을 변경할 수 있기 때문이다.


## 배운 점

- 오늘 처음으로 스터디를 진행했다. 서로 이해하지 못한 부분을 질문하고 설명하는 과정이 재미있었다.

- 혼자 공부할 때는 넘어갔던 내용도 다른 사람의 질문을 통해 더 깊게 생각해 볼 수 있었다. 특히 같은 개념도 서로 다른 관점에서 질문하다 보니 개념을 단순히 외우는 것이 아니라 왜 그렇게 동작하는지 생각해 볼 수 있었다.

- 앞으로도 배운 내용을 단순히 정리하는 데 그치지 않고, 다른 사람에게 설명할 수 있을 정도로 이해했는지 확인하면서 공부해야겠다고 느꼈다.
